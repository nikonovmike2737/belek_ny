# BELEK NY: правило публикации только по дельте

Статус: HARD GATE. Обязательное правило для каждого 3-часового мониторинга и каждой публикации в прод.

## Главное правило

Прод обновляется только тогда, когда мониторинг нашёл подтверждённое содержательное изменение относительно текущего опубликованного состояния.

Сам факт очередного запуска мониторинга никогда не является причиной переписывать Google Drive, пересобирать PDF, создавать commit, запускать GitHub Actions или GitHub Pages.

`NO DELTA = NO WRITE = NO COMMIT = NO DEPLOY`.

## Обязательная последовательность

1. До мониторинга прочитать текущее опубликованное состояние: canonical HTML и PDF на Google Drive, `main` на GitHub, структурированные данные цен и реестр категорий номеров.
2. Построить нормализованный слепок текущих опубликованных фактов и цен.
3. Отдельно провести мониторинг разрешённых источников.
4. Нормализовать результат мониторинга к той же схеме.
5. Сопоставить результат с опубликованным слепком поле в поле.
6. Не считать дельтой служебные отличия: новое время проверки источника, `checked_at`, идентификатор запуска, параметр против кэша, внутренний номер версии, новое время публикации само по себе, повторную генерацию эквивалентного PDF и изменения форматирования без изменения факта.
7. Если содержательная дельта пуста, остановиться. Ничего не писать и не публиковать.
8. Если дельта есть, проверить доказательность и сопоставимость каждого изменившегося факта.
9. Внести только подтверждённую дельту. Неизменившиеся факты не трогать.
10. Пройти проверки HTML, PDF, структурированных данных и readback.
11. Только после PASS записать оба canonical-файла и разрешить синхронизацию GitHub.
12. GitHub Pages может публиковаться только из commit, содержащего реальное изменение артефактов или данных. Trigger-only, timestamp-only и empty commits запрещены.
13. После успешной публикации новое состояние становится базой следующего мониторинга.

## Что считается содержательной дельтой

- изменилась сопоставимая цена;
- изменилась сопоставимая доступность;
- добавилась, исчезла или переименовалась категория номера;
- изменились существенные условия питания, новогоднего ужина, обязательных доплат или отмены;
- изменились важные зимние услуги или инфраструктура;
- появились сильные новые доказательства, снимающие важную неопределённость;
- рейтинг или рекомендация изменились из-за подтверждённых новых фактов.

Повторная проверка того же источника без изменения факта не является дельтой.

## Цены

Для каждой сопоставимой опубликованной цены сохраняется непосредственно предыдущая опубликованная сопоставимая цена.

- `current > previous` -> цена выросла -> `up` и красная `↑`;
- `current < previous` -> цена снизилась -> `down` и зелёная `↓`;
- `current == previous` -> цена не изменилась -> `same`, стрелки нет.

Сравнение разрешено только при совпадении дат поездки, состава гостей, сопоставимой категории номера, питания и валюты. Несопоставимые предложения не получают статус роста или снижения.

Время предыдущего и текущего опубликованного обновления цен хранится отдельно по правилам `docs/PRICE_UPDATE_TIMESTAMPS_RULE.md` и меняется только при реально опубликованной дельте цен.

## Поведение при отсутствии изменений

Если содержательной дельты нет, запрещено:

- менять видимое время обновления;
- менять внутреннюю версию ради публикации;
- пересобирать и заменять эквивалентный PDF;
- переписывать canonical Drive-файлы;
- трогать `.github/belek-sync-trigger` или аналогичный файл;
- создавать commit только для запуска workflow;
- создавать пустой commit;
- запускать деплой только потому, что прошло три часа.

## Инвариант прода

Любой production deployment должен объясняться цепочкой:

`опубликованное состояние -> подтверждённая дельта мониторинга -> обновлённые HTML/PDF/данные -> проверенный commit с изменениями -> Pages`.

Если подтверждённой дельты в этой цепочке нет, публикация запрещена.
