# BELEK NY: правило публикации только по дельте

Статус: HARD GATE. Обязательное правило для каждого 3-часового мониторинга и каждой публикации в прод.

## Главное правило

Прод обновляется только тогда, когда мониторинг нашёл подтверждённое содержательное изменение относительно текущего опубликованного состояния.

Сам факт очередного запуска мониторинга никогда не является причиной переписывать Google Drive, пересобирать PDF, создавать commit, запускать GitHub Actions или GitHub Pages.

`NO DELTA = NO WRITE = NO COMMIT = NO DEPLOY`.

## Обязательная последовательность

1. До мониторинга прочитать текущее опубликованное состояние: canonical HTML и PDF на Google Drive, `main` на GitHub, структурированные данные цен, реестр категорий номеров и канонический список официальных сайтов отелей.
2. Построить нормализованный слепок текущих опубликованных фактов, цен и выбранных официальных URL.
3. Отдельно провести мониторинг разрешённых источников.
4. Для каждого официального сайта проверить языковые версии строго в порядке RU -> EN -> DE -> TR и выбрать первую рабочую официальную версию конкретного отеля.
5. Нормализовать результат мониторинга к той же схеме.
6. Сопоставить результат с опубликованным слепком поле в поле.
7. Не считать дельтой служебные отличия: новое время проверки источника, `checked_at`, идентификатор запуска, параметр против кэша, внутренний номер версии, новое время публикации само по себе, повторную генерацию эквивалентного PDF и изменения форматирования без изменения факта.
8. Если содержательная дельта пуста, остановиться. Ничего не писать и не публиковать.
9. Если дельта есть, проверить доказательность и сопоставимость каждого изменившегося факта.
10. Внести только подтверждённую дельту. Неизменившиеся факты не трогать.
11. Пройти проверки HTML, PDF, структурированных данных и readback.
12. Только после PASS записать изменяемые canonical-файлы и разрешить синхронизацию GitHub.
13. GitHub Pages может публиковаться только из commit, содержащего реальное изменение артефактов или данных. Trigger-only, timestamp-only и empty commits запрещены.
14. После успешной публикации новое состояние становится базой следующего мониторинга.

## Что считается содержательной дельтой

- изменилась сопоставимая цена;
- изменилась сопоставимая доступность;
- добавилась, исчезла или переименовалась категория номера;
- изменились существенные условия питания, новогоднего ужина, обязательных доплат или отмены;
- изменились важные зимние услуги или инфраструктура;
- появились сильные новые доказательства, снимающие важную неопределённость;
- рейтинг или рекомендация изменились из-за подтверждённых новых фактов;
- изменилась первая рабочая официальная языковая версия сайта отеля по обязательной цепочке RU -> EN -> DE -> TR, из-за чего должен измениться URL кнопки `Сайт отеля`.

Повторная проверка того же источника без изменения факта не является дельтой. Недоступность одной языковой версии без изменения выбранного рабочего URL тоже не является прод-дельтой, но должна попасть в отчет запуска.

## Языковая дельта официального сайта

Для каждого отеля на каждом запуске приоритет пересчитывается заново: RU, затем EN, затем DE, затем TR. Выбирается первая рабочая официальная версия конкретного отеля.

Если новая выбранная версия отличается от опубликованной, это содержательная неценовая дельта. Можно обновить `data/hotel-site-links.json` и HTML-кнопку `Сайт отеля`. Такая дельта не меняет цены, ценовые стрелки и времена `previous_price_update_at` / `current_price_update_at`.

Если не работает ни одна допустимая версия, сохраняется последний подтвержденный официальный URL, проблема отражается в отчете, ценовой мониторинг продолжается.

## Цены

Для каждой сопоставимой опубликованной цены сохраняется непосредственно предыдущая опубликованная сопоставимая цена.

- `current > previous` -> цена выросла -> `up` и красная `↑`;
- `current < previous` -> цена снизилась -> `down` и зелёная `↓`;
- `current == previous` -> цена не изменилась -> `same`, стрелки нет.

Сравнение разрешено только при совпадении дат поездки, состава гостей, сопоставимой категории номера, питания и валюты. Несопоставимые предложения не получают статус роста или снижения.

Время предыдущего и текущего опубликованного обновления цен хранится отдельно по правилам `docs/PRICE_UPDATE_TIMESTAMPS_RULE.md` и меняется только при реально опубликованной дельте цен.

## Поведение при отсутствии изменений

Если содержательной дельты нет, запрещено:

- менять видимое время обновления;
- менять внутреннюю версию ради публикации;
- пересобирать и заменять эквивалентный PDF;
- переписывать canonical Drive-файлы;
- трогать `.github/belek-sync-trigger` или аналогичный файл;
- создавать commit только для запуска workflow;
- создавать пустой commit;
- запускать деплой только потому, что прошло три часа.

## Инвариант прода

Любой production deployment должен объясняться цепочкой:

`опубликованное состояние -> подтверждённая дельта мониторинга -> обновлённые HTML/PDF/данные -> проверенный commit с изменениями -> Pages`.

Для языковой ссылки допустима более узкая цепочка: `опубликованный URL -> подтвержденная смена первой рабочей языковой версии RU/EN/DE/TR -> обновленные данные и HTML -> проверенный commit -> Pages`.

Если подтверждённой дельты в этой цепочке нет, публикация запрещена.
