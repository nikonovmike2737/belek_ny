# BELEK NY: время текущего и предыдущего обновления цен

Статус: обязательное правило для блока «Стоимость номеров», HTML, PDF и 3-часового мониторинга.

## Что храним

Система хранит два времени в часовом поясе `Europe/Moscow`:

- `previous_price_update_at` - время предыдущего успешно опубликованного состояния цен;
- `current_price_update_at` - время текущего успешно опубликованного состояния цен.

Эти времена относятся именно к публикациям цен. Они не равны времени последней правки дизайна, текста, PDF или другой части отчёта.

В canonical HTML те же значения хранятся на блоке легенды в атрибутах:

- `data-previous-price-update-at`;
- `data-current-price-update-at`.

В репозитории они зеркалируются в `data/price-update-state.json`. Файл должен формироваться детерминированно из canonical HTML, без `generated_at`, `checked_at` или другого текущего времени, чтобы пустой запуск мониторинга не создавал ложную дельту.

## Что показываем пользователю

Над таблицей цен показываем:

`Изменение с прошлого обновления цен ДД.ММ, ЧЧ:ММ`

Дата и время в этой строке всегда берутся из `previous_price_update_at`.

Пример текущей инициализации:

- предыдущее опубликованное состояние цен: `2026-09-10T13:14:00+03:00`;
- текущее опубликованное состояние цен: `2026-09-10T14:00:00+03:00`;
- публичная строка: `Изменение с прошлого обновления цен 10.09, 13:14`.

## Как двигаются времена

Времена меняются только при реальной подтверждённой дельте цен, которая успешно опубликована.

Перед публикацией новой ценовой дельты:

1. взять текущее `current_price_update_at` и перенести его в `previous_price_update_at`;
2. записать время новой публикации цен в `current_price_update_at`;
3. для всех 60 ценовых ячеек перенести прежний `data-current-price-eur` в `data-prev-price-eur`;
4. записать новые текущие цены в `data-current-price-eur`; для неизменившихся ячеек новое текущее значение совпадает с предыдущим;
5. пересчитать `data-price-trend`: рост, снижение или отсутствие изменения;
6. обновить публичную строку легенды по новому `previous_price_update_at`;
7. обновить HTML и PDF транзакционно;
8. только после успешной публикации считать новые времена текущим production state.

Пример: если следующее реальное обновление цен опубликовано 10 сентября в 17:14, состояние становится:

- `previous_price_update_at = 2026-09-10T14:00:00+03:00`;
- `current_price_update_at = 2026-09-10T17:14:00+03:00`;
- легенда показывает `Изменение с прошлого обновления цен 10.09, 14:00`.

## Когда времена НЕ меняются

Не менять оба значения, если:

- очередной мониторинг не нашёл ценовой дельты;
- изменилось только время проверки источника;
- источник повторно вернул ту же цену;
- появилась несопоставимая цена, которую нельзя честно сравнить;
- меняются только текст, дизайн, расположение стрелок, PDF-вёрстка, источники без изменения цены, услуги или другие непрейсовые данные;
- пересобран PDF с теми же ценами;
- произошло техническое обновление workflow.

В частности, текущая правка формулировки легенды не считается новым обновлением цен. Поэтому начальные значения остаются 13:14 и 14:00 10 сентября 2026 года.

## Связь со стрелками

Стрелка показывает изменение текущей цены относительно цены из непосредственно предыдущего опубликованного состояния, которое соответствует `previous_price_update_at`.

- красная `↑`: текущая сопоставимая цена выше предыдущей;
- зелёная `↓`: текущая сопоставимая цена ниже предыдущей;
- без стрелки: цена не изменилась.

Стрелка и дата в легенде описывают одну и ту же базу сравнения.

## Публикация только по дельте

Это правило подчиняется `docs/DELTA_ONLY_PRODUCTION_POLICY.md`. Пустой 3-часовой мониторинг не сдвигает время цен, не меняет документы, не создаёт commit и не запускает деплой.
