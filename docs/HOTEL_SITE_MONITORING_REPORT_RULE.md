# BELEK NY: отчет о доступности официальных сайтов отелей

Статус: обязательное правило для каждого трехчасового мониторинга.

Каждый запуск до или параллельно с проверкой цен должен проверить доступность всех официальных сайтов из `data/hotel-site-links.json`.

## Порядок языков

Для каждого отеля проверка выполняется строго по цепочке RU -> EN -> DE -> TR.

1. Сначала русская версия.
2. Если RU недоступна, английская.
3. Если EN недоступна, немецкая.
4. Если DE недоступна, турецкая.
5. Используется первая рабочая официальная версия конкретного отеля.

Если не работает ни одна из четырех версий, сохраняется последний подтвержденный официальный адрес, но в отчете это помечается как проблема доступности. Агрегатор, поставщик или другой отель не подставляются.

Проверка сайта не является блокирующим условием для мониторинга цен. Если официальный сайт одного или нескольких отелей не отвечает, мониторинг должен продолжиться по всем остальным разрешенным источникам и завершить расчет ценовой дельты.

## Обязательная строка отчета

Если все выбранные ссылки доступны и запасной язык не понадобился: `Сайты отелей: 10/10 доступны`.

Если для отеля сработал запасной язык, добавить это в ту же строку, например: `Сайты отелей: 10/10 доступны; Voyage: RU недоступен, используется EN`.

Если ни одна допустимая языковая версия не работает: `Сайты отелей: недоступен <отель>; проверены RU, EN, DE, TR; последний подтвержденный адрес <URL>`.

Если сайт отвечает перенаправлением на устойчивый официальный адрес того же отеля, канонический адрес нужно обновить при содержательной дельте. Если перенаправление ведет на другой объект, агрегатор или нерелевантную страницу, такая версия считается нерабочей и проверяется следующий язык по цепочке.

Недоступность одной языковой версии сама по себе не меняет цену, стрелку цены, рейтинг или рекомендации. Но если из-за проверки изменился фактически выбранный рабочий URL, это содержательная неценовая дельта ссылки и она может быть опубликована в прод. Ценовые часы при этом не меняются.

Публикация в прод по-прежнему разрешена только по реальной содержательной дельте согласно `docs/DELTA_ONLY_PRODUCTION_POLICY.md`.
