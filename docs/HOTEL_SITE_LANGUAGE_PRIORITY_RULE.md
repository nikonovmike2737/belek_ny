# BELEK NY: порядок языков для официальных сайтов отелей

Статус: обязательное правило для кнопок `Сайт отеля`, трехчасового мониторинга, проверки ссылок и публикации.

## Главное правило

Для каждого отеля используется первая работающая официальная языковая версия в строгом порядке:

1. Русская `ru`.
2. Английская `en`.
3. Немецкая `de`.
4. Турецкая `tr`.

Проверка всегда начинается заново с русского языка. Нельзя навсегда оставлять английскую, немецкую или турецкую версию только потому, что русская была недоступна в предыдущем запуске.

Если русская версия не отвечает, нужно проверить английскую. Если английская работает, она становится текущей ссылкой кнопки `Сайт отеля`. Если английская не отвечает, проверяется немецкая. Если немецкая работает, используется она. Если немецкая тоже не отвечает, проверяется турецкая как национальная версия сайта. Если турецкая работает, используется она.

Если не работает ни одна из четырех языковых версий, нельзя подставлять агрегатор, поставщика, страницу другого отеля сети или нерелевантную страницу бренда. В карточке сохраняется последний подтвержденный официальный адрес, а в отчете запуска явно указывается, что сейчас не удалось открыть ни одну допустимую языковую версию. Мониторинг цен при этом продолжается по другим разрешенным источникам.

## Что значит `работает`

Языковая версия считается рабочей только если:

- открывается без ошибки доступа;
- остается на официальном домене отеля или официальной сети;
- ведет именно на тот отель, который указан в карточке;
- не перенаправляет на агрегатор, другой объект или общую нерелевантную страницу;
- выбранный язык действительно соответствует проверяемой версии.

## Источник истины

Канонический список хранится в `data/hotel-site-links.json`.

В корне файла обязательно хранятся:

- `language_policy = ru-en-de-tr-fallback`;
- `language_priority = [ru, en, de, tr]`.

Для каждой записи хранятся точное название отеля, текущий канонический URL, подтверждение личности отеля, предпочтительный язык `ru`, текущий фактически выбранный язык `selected_language` и подтверждение языковой версии.

## Трехчасовой мониторинг

Каждый запуск обязан:

1. Начать проверку с русской версии.
2. При недоступности RU проверить EN.
3. При недоступности EN проверить DE.
4. При недоступности DE проверить TR.
5. Выбрать первую рабочую версию по этому порядку.
6. Сопоставить выбранный адрес с текущим каноническим адресом.
7. Если адрес или выбранный язык изменился, считать это содержательной неценовой дельтой ссылки.
8. Обновить карточку и `data/hotel-site-links.json` только при реальном изменении выбранной рабочей версии.

Смена языковой версии не является ценовой дельтой. Она не меняет цены, стрелки и `previous_price_update_at` / `current_price_update_at`.

## Отчет

Если все текущие выбранные ссылки доступны, отчет содержит `Сайты отелей: 10/10 доступны`.

Если для какого-либо отеля сработал запасной язык, это нужно добавить к строке отчета, например: `Voyage: RU недоступен, используется EN`.

Если не сработала ни одна версия, указать отель и все проверенные языки.

## Публикация

Изменение текущей рабочей языковой версии является содержательной дельтой URL и может быть опубликовано в прод как неценовая дельта. Если выбранный URL не изменился, сам факт очередной проверки не является дельтой.

Действует правило `NO DELTA = NO WRITE = NO COMMIT = NO DEPLOY`.
